> 部署方式：Linux systemd、PM2，或 Windows 任务计划程序

## 1. 更新前检查与备份

> 以下命令以 Linux 路径 `/opt/canyin/web-mysql` 为例，请替换成实际目录。

### 1.1 确认当前版本与工作区状态

```bash
cd /opt/canyin/web-mysql
git status
git log -1 --oneline
git describe --tags --always
```

工作区必须是干净的。如果服务器上直接改过代码，先提交或备份，避免 `git pull` 冲突。

### 1.2 备份数据库

```bash
mkdir -p /opt/canyin/backup
mysqldump --single-transaction --routines --triggers \
  -u root -p canyin \
  > /opt/canyin/backup/canyin_$(date +%F_%H%M).sql
```

确认备份文件不为空：

```bash
ls -lh /opt/canyin/backup/canyin_*.sql
```

### 1.3 备份上传图片和配置

```bash
tar -czf /opt/canyin/backup/uploads_$(date +%F_%H%M).tar.gz \
  -C /opt/canyin/web-mysql uploads

cp /opt/canyin/web-mysql/.env \
   /opt/canyin/backup/env_$(date +%F_%H%M).bak
```

`uploads/` 存的是原图，数据库里只有索引；只备份数据库无法恢复图片。  
如果图片目录很大，至少确认它有独立磁盘快照或异地备份。

### 1.4 记录当前版本，便于回滚

```bash
git rev-parse HEAD > /opt/canyin/backup/previous_commit.txt
git tag --points-at HEAD
```

## 2. 获取新版本代码

### 2.1 正常更新（推荐）

```bash
cd /opt/canyin/web-mysql
git fetch --all --tags
git pull --ff-only origin main
```

如果使用版本标签发布：

```bash
git checkout v2.2.0
```

> 生产环境建议固定到标签，而不是长期跟随 `main`。  
> `--ff-only` 可以避免服务器上产生意外的合并提交。

### 2.2 首次在该服务器部署

如果服务器目录还不是 Git 仓库：

```bash
cd /opt/canyin
git clone <仓库地址> web-mysql
cd web-mysql
```

然后把原有的 `.env` 和 `uploads/` 放回对应位置。

### 2.3 安装依赖

运行依赖只有 `mysql2`，按锁文件安装：

```bash
cd /opt/canyin/web-mysql
npm ci --omit=dev
```

> 若之前部署过 v2.2.1（sharp 版），本次回滚后可顺手清理：
> `npm uninstall sharp`，并删除 `uploads/.cache/` 目录。

如果服务器 Node 版本低于 18，先升级 Node。可以用：

```bash
node -v
```

确认输出为 `v18.x` 或更高。

### 2.4 检查 `.env`

打开 `.env`，确认数据库配置没有变化，并按需增加：

```ini
# 1：前台免口令新增商户、上传配图（默认）
# 0：新增和上传也需要 ADMIN_TOKEN
PUBLIC_ADD=1
```

如果是公网环境、不希望陌生人写入，建议改为：

```ini
PUBLIC_ADD=0
```

改完 `.env` 必须重启服务才会生效。

### 2.5 数据库是否需要升级

本版本**没有新增表或字段**，不需要执行迁移。  
如果数据库尚未初始化，或怀疑视图缺失，可以执行（脚本是可重复执行的）：

```bash
mysql -u root -p < sql/schema.sql
```

> `schema.sql` 只负责建库、建表、建视图，不会删除已有数据；但仍建议先完成 1.2 的数据库备份。

## 3. 重启服务

### 3.1 Linux · systemd

```bash
sudo systemctl restart canyin-web
sudo systemctl status canyin-web --no-pager
sudo journalctl -u canyin-web -n 50 --no-pager
```

如果服务名不是 `canyin-web`，用实际名称替换：

```bash
systemctl list-units --type=service | grep -i canyin
```

### 3.2 Linux · PM2

```bash
pm2 restart canyin-web --update-env
pm2 save
pm2 logs canyin-web --lines 50
```

如果 PM2 进程名不同，先执行 `pm2 list` 查看。

### 3.3 Windows · 任务计划程序（CanyinWeb）

在 PowerShell 中执行：

```powershell
Stop-ScheduledTask  -TaskName CanyinWeb
Start-ScheduledTask -TaskName CanyinWeb
Get-ScheduledTask   -TaskName CanyinWeb | Select-Object TaskName, State
Get-Content .\logs\server.log -Tail 50
```

如果是手动双击 `scripts\start-server.bat` 启动的，先关闭原来的 Node 窗口，再重新启动。

> Windows 上如果 MySQL 是系统服务，确认它是自动启动：  
> `Get-Service *mysql*`，启动类型应为 `Automatic`。

### 3.4 反向代理

本次没有修改 Nginx 路由，通常不需要改配置。  
但上传原图仍要确认请求体上限：

```nginx
client_max_body_size 100m;
```

修改 Nginx 后执行：

```bash
sudo nginx -t && sudo systemctl reload nginx
```

## 4. 更新后验证

### 4.1 接口检查

```bash
curl -s http://127.0.0.1:3000/api/health
curl -s http://127.0.0.1:3000/api/config
```

预期：

- `/api/health` 返回 `"ok": true`；
- `/api/config` 返回 `"publicAdd": true`（或按 `.env` 设置为 `false`）。

如果 `/api/health` 返回 503，先检查 MySQL 是否启动、`.env` 数据库账号是否正确。

### 4.2 前台免口令新增与图片轮播

1. 打开首页，点右上角「＋ 登记商户」；
2. 确认表单里**没有管理口令输入框**；
3. 填写店名，上传**两张以上**照片；点其中一张小图，应提示「已设为封面」；
4. 点「保存并查看」；
5. 保存成功后应自动打开新商户详情；
6. 详情页图片应**自动轮播**：左右箭头、底部圆点、右下角「当前 / 总数」计数可用；
   手机上可左右滑动切换，电脑上键盘 ← / → 可切换，鼠标悬停时暂停；
7. 详情页应出现「高德导航」和「查看地图」；
8. 返回首页，新商户卡片的封面应是刚才**设为封面的那张图**（即第一张）。

验证完成后，可在管理端删除这条测试商户。

### 4.3 定位与高德导航

- 手机通过 **HTTPS** 打开页面，点「📍 获取当前位置」，经纬度应自动回填；
- 点「在高德地图确认位置」，手机应唤起高德地图 App（未安装则打开网页版）；
- 详情页点「高德导航」，应直接进入高德 App 的驾车导航。

> 浏览器只允许在 **HTTPS 或 localhost** 下获取定位。  
> 用 `http://局域网IP:3000` 访问时定位会被拦截，这是浏览器安全限制，不是接口故障。此时可手动填写经纬度。

### 4.4 管理端权限仍然有效

1. 打开 `/admin`，输入 `ADMIN_TOKEN` 登录；
2. 编辑一条商户，确认可以保存；
3. 删除测试商户，确认可以删除；
4. 退出登录后直接调用修改/删除接口，应返回 401。

### 4.5 日志检查

```bash
# systemd
sudo journalctl -u canyin-web -n 100 --no-pager

# PM2
pm2 logs canyin-web --lines 100

# Windows
Get-Content .\logs\server.log -Tail 100
```

重点看是否有 `ECONNREFUSED`、`ER_ACCESS_DENIED_ERROR`、`413`、`401` 等错误。

## 5. 回滚方案

如果更新后出现无法快速修复的问题，按以下顺序回滚。

### 5.1 回滚代码

先找到更新前的提交：

```bash
cat /opt/canyin/backup/previous_commit.txt
```

然后：

```bash
cd /opt/canyin/web-mysql
git checkout <更新前的提交或标签>
npm ci --omit=dev
sudo systemctl restart canyin-web
```

> 不要直接 `git reset --hard` 覆盖服务器上未提交的修改；先确认 `git status`。

### 5.2 回滚数据库

本版本没有表结构变更，通常不需要回滚数据库。  
如果确实发生数据异常：

```bash
mysql -u root -p canyin < /opt/canyin/backup/canyin_YYYY-MM-DD_HHMM.sql
```

> 恢复数据库会覆盖恢复点之后的新数据，执行前先再备份一次当前库。

### 5.3 回滚图片

```bash
cd /opt/canyin/web-mysql
mv uploads uploads_broken_$(date +%F_%H%M)
tar -xzf /opt/canyin/backup/uploads_YYYY-MM-DD_HHMM.tar.gz
```

### 5.4 回滚后验证

重复第 4 节的接口检查、前台新增、管理端编辑删除和日志检查。

## 6. 安全与运维注意事项

1. **公开新增是有意放开的**  
   `PUBLIC_ADD=1` 时，知道地址的人都能新增商户并上传图片。  
   如果部署在公网且不希望被陌生人写入，设置 `PUBLIC_ADD=0` 并重启。

2. **修改/删除仍受保护**  
   `PUT /api/shops/:id`、`DELETE /api/shops/:id`、`DELETE /api/upload` 仍然要求 `ADMIN_TOKEN`。  
   上线前务必把 `ADMIN_TOKEN` 改成足够长的随机串，不要保留 `change-me`。

3. **上传限制**  
   单请求上限 64MB，仅按扩展名判断图片类型。公网环境建议在 Nginx 增加：
   - `client_max_body_size`；
   - 上传频率限制；
   - `Content-Type` 校验；
   - 上传目录禁止目录浏览。

4. **HTTPS**  
   手机定位依赖 HTTPS。生产环境建议使用 Nginx/Caddy 配置证书；  
   如果只用 HTTP，定位按钮会提示失败，但手动填写坐标仍可保存。

5. **备份**  
   数据库和 `uploads/` 必须一起备份。只备份数据库无法恢复原图。

## 7. 常见问题

| 现象 | 排查 |
|---|---|
| 前台仍显示口令输入框 | 服务端没重启，或 `/api/config` 仍返回 `publicAdd:false`；检查 `.env` 的 `PUBLIC_ADD` 并重启 |
| 前台新增返回 401 | `PUBLIC_ADD=0`，或旧版服务端未更新；检查 `/api/config` |
| 保存返回 503 | MySQL 未启动，或 `.env` 数据库账号/库名不对 |
| 上传返回 413 | Nginx `client_max_body_size` 太小 |
| 定位失败 | 页面不是 HTTPS/localhost，或浏览器拒绝了定位权限；可手动填写坐标 |
| 高德导航没唤起 App | 手机未安装高德地图，或浏览器拦截了外部 App；用「查看地图」兜底 |
| 页面还是旧样式 | 浏览器缓存；强制刷新（Ctrl+F5），确认页面引用的是 `app.js?v=9`、`style.css?v=8` |
| 详情图片不轮播 | 单图商户本来就不显示轮播控件；多图仍不轮播多为缓存了旧 `app.js`，强制刷新即可 |
| 管理端口令不对 | 改 `.env` 后没有重启；`ADMIN_TOKEN` 与服务端不一致 |
